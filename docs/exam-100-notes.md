# 考试卷子 100 题（Exam Paper, 100 Scenarios）

**日期：** 2026-11-21
**状态：** 完成。100 题 + 多轮标注 + 系统实测全部跑完，测试全绿。

## 卷子

`taiji_field/data/exam_100.json`：100 个情境，5 类 × 20 题
（工作决策 / 谈判 / 关系 / 创意 / 日常），每题一个提议演化
（起始卦 + 动爻 + 落点卦 + 一句理由）。落点卦由起始卦 + 动爻
算出（`scripts/build_exam_100.py`），不是手填的。

**标签是草稿，不是标准答案。** 这一点与 v1 卷子相同，不同的是
标注方式（见下）。

## 标注方法（与 roadmap 的偏差，如实写明）

Roadmap 第 6 节要求"3 个人独立标，不一致的丢掉或讨论"。
本次做不到 3 个人，改成以下方案——**这是计划内的偏差，
不是 3 人共识，文件里已明确写明，升级要等真人审阅**：

- **Pass A：** 作者按卦义推理（起始卦 + 动爻 + 理由），与 v1
  卷子同款做法。
- **Pass B：** 不同的方法——接地编码器共振取 top-1 起始卦，
  再由 Phase 1 推理器给出路径；作者随后人工检查分歧。
  Pass B 从不覆盖 Pass A，只确认或打旗。
- **Pass C：待真人审阅。** 没有第二个通用 LLM 可用：
  Meta Model API 连接器只是 FixLens 照片分析，不是通用对话模型；
  而基线模型（DeepSeek `deepseek-chat`）不能同时当标注员，
  否则比较就有偏。
- **分歧处理：** A 与 B 一致，取一致的标签；不一致则没有多数，
  按平局处理——取 Pass A，并把该题打旗（`flagged: true`），
  等真人审阅时优先看。

## 一致率（实测）

| | 一致数 / 100 |
|---|---|
| 起始卦一致（A vs B） | **10** |
| 动爻一致（A vs B） | **10** |
| 完整一致（起始卦 + 动爻） | **1** |
| 打旗（待真人审阅） | **99** |

只有 1 题是两轮完全一致的。起始卦一致率只有 10%。

## 人工检查分歧（抽查 10 题）

作者读了 10 个分歧样本（每类 2 题），判断 B 的提议是不是
"合理的另一种读法"：

- 约 1 题 B 完全合理（F01：起止卦一致，只动爻不同，都是"夬"的决断）。
- 约 5 题 B 只抓住了情境的一半：F20（讼抓住了价格争执、丢了"彼此受益"）、
  F51（同人抓住了聚会、丢了"低调"）、F61（否抓住了卡住、丢了"内部积弊要整治"）、
  F81（需抓住了等待休息、丢了"滋养根本"）、F91（大过抓住了负担、丢了"滋养"）。
- 约 4 题 B 较弱：F10（年终奖公平→家人）、F30（长租锁定→既济）、
  F40（对赌负担→既济）、F71（包装与内容→小畜）。

结论：B 的提议大多不是胡说，而是"抓住了情境的某一个侧面，
但不是作者认为最核心的那个"。也就是说，**短情境对应哪一卦
本身就是欠定的**——同一个情境有多个站得住脚的读法。
这正是 roadmap 要求 3 人共识的原因，也是本次 99 题打旗的原因。
在真人审阅之前，任何"命中率"都只是"与单人草稿标签的一致程度"。

## 系统在 100 题上的实测（Phase 2 推理器）

`scripts/run_exam_100.py`，用 30 题上拟合好的权重
（w1=0.5, w2=2.0, w3=0.5, w4=0.2，见 `exam_report_v2.json`），
**没有在 100 题上重新调权重**。报告在
`taiji_field/data/exam_report_100.json`（生成物，不入库；
`baseline` 字段为 null——100 题的 LLM 基线是后续工作）。

| | top-1 | top-3 | 完整路径 |
|---|---|---|---|
| Phase 2 推理器（100 题） | **10/100** | **21/100** | **1/100** |

分项 top-1：工作决策 3/20，谈判 2/20，关系 2/20，创意 1/20，
日常 2/20——没有哪一类明显好，全面都低。
完整路径只有 1 题（关系类）。

## 最值得注意的落差：30 题 vs 100 题

| | top-1（薄文档） | top-1（丰富文档） |
|---|---|---|
| 30 题 | 15/30（50%） | 11/30（37%） |
| 100 题 | 7/100（7%） | 10/100（10%） |

薄文档在 100 题上的 7/100 是本次的临时对照（不入库的编码，
只为诊断用）。丰富文档在 100 题上的 10/100 与 Pass B 的
起始卦一致率 10/100 是同一件事（top-1 不依赖推理器）。

**30 题的 50% 很可能被高估了。** 两种可能都存在，无法区分：

1. **标签作者的因素：** 100 题的 Pass A 是短时间内一人写出的
   100 个标签，质量与 30 题未必相同；而且 30 题的标签写于
   Phase 1，作者当时对编码器的行为已有了解。
2. **卷子本身的因素：** 100 题的情境更多样、更日常，文本里
   "等/先/还是/怎么办"这类商量语气很重，编码器被大量引向
   需（19 次）、家人（14 次）、讼（10 次）等几个通用卦；
   薄文档对照里也是需 15 次、家人 8 次——塌缩不是丰富文档
   造成的，两种文档都有。

不管是哪种，结论一样：**30 题上的数字不能外推。**
更大的卷子、更多人标注，是 Phase 2 笔记里就写明的下一步；
本次把它做出来了，数字不好看，但这正是测量要做的事。

## 诚实边界

1. **标签没审过。** 99/100 打旗，Pass C 待真人审阅。
   在此之前，10/100、1/100 这些数字衡量的是"与单人草稿
   的一致程度"，不是"正确程度"。
2. **Pass B 不是独立的人。** 它是同一台编码器 + 推理器，
   只是换了个用法。A 与 B 的一致率低，说明"人想的"和
   "编码器找的"分歧很大，但这不等于"人一定对"——
   上面抽查里也有 B 更合理的可能（F01 的动爻之争）。
3. **权重是 30 题上调出来的。** 100 题实测用的权重是在
   30 题草稿标签上拟合的，本身就带过拟合嫌疑（Phase 2
   的留出检验已经说明它不泛化）。100 题的 1/100 路径命中
   与 Phase 1 在 30 题上的 2/30 放在一起看，不宜直接比较。
4. **100 题的 LLM 基线没做。** `exam_report_100.json` 的
   `baseline` 为 null。没有基线，"赢没赢过 token 预测"
   依然无法判定（见 [docs/baseline-v1.md](baseline-v1.md)）。
