# Phase 1 笔记：接地与共振（Grounding + Resonance）

**日期：** 2026-11-21
**状态：** Phase 1 完成。编码器、共振推理、解释器、考试卷子、考试 harness 全部能跑，测试全绿。

Phase 0 的结论是：骨架作为"结构"成立，作为"智能"未验证，卡在动力学与接地两个空白。
Phase 1 填的是接地那一半：情境 → 态的映射第一次有了可运行的机制（共振检索），
而不是只靠人工判断。动力学那一半仍然没有——见"诚实边界"。

---

## 建了什么

- **接地编码器 v1**（`taiji_field/grounding.py`）：每个卦一个文档（卦名 + 一句作者写的现代中文解读），
  用 `BAAI/bge-small-zh-v1.5`（sentence-transformers，CPU）编码成向量；情境文本编码后按余弦相似度
  找最共振的卦，返回 top-3。64 个卦文档的 embedding 缓存在 `taiji_field/data/embeddings.npz`，
  用 `python scripts/build_embeddings.py` 重建。
- **共振推理 v1**（`taiji_field/reasoning.py`）：从 top-1 卦出发，沿变爻边展开 1–3 步，
  枚举全部简单路径（≤156 条），按"落点共振 − 0.05×步数"排名，输出最好的一条。
- **解释器 v1**（`taiji_field/interpreter.py`）：模板中文解释——动了哪一爻、两端卦的一句解读、
  一句综合。模板而已，见下。
- **考试卷子 v1**（`taiji_field/data/exam_v1.json` + `docs/exam-v1.md`）：30 个情境
  （工作决策 / 谈判 / 关系 / 创意 / 日常各 6 题），每题一个提议演化（起始卦 + 动爻 + 落点卦 + 一句理由）。
  **标签是草稿，等待 Wen 审阅，不是标准答案。**落点卦由起始卦 + 动爻算出，不是手填的
  （`scripts/build_exam.py`，测试锁定一致性）。
- **考试 harness**（`taiji_field/exam.py`）：对每题跑完整流程（编码 → 匹配 → 推理），
  写 JSON 报告（`taiji_field/data/exam_report.json`，生成物，不入库）。

## 考试结果（诚实数字，2026-11-21 实测，bge-small-zh-v1.5）

- top-1 命中提议起始卦：**15/30**
- top-3 命中：**20/30**
- 完整路径（起始卦 + 动爻全对）：**2/30**

不管数字是多少，它都是诚实测出来的。卷子标签本身是草稿——命中率低可能说明编码器不行，
也可能说明提议的标签不行，两者都可能。Wen 审阅标签之后，这个数字才有比较意义。

值得注意的分化：起始卦 top-1 有一半命中（15/30），但完整路径只有 2/30。
也就是说，共振找"现在像哪一卦"有一半靠谱，而"该动哪一爻"几乎全靠猜——
路径排名只看落点共振，没有方向信息，这是 v1 启发式的直接后果，也是 Phase 2
要解决的动力学问题。报告全文见 `taiji_field/data/exam_report.json`（生成物，不入库）。

## 诚实边界（读代码之前先读这段）

1. **解释是模板，不是理解。** 每步的"为什么"只是"动了第 N 爻 + 两端卦的一句解读"。
   系统不知道为什么动这一爻。输出里任何听起来像"想明白了"的句子，都是模板的措辞。
2. **排名是启发式，不是动力学。** "落点共振 − 步数惩罚"只是在 1–3 步内找离情境最近的落点。
   没有能量函数，就没有"下坡"的方向——Phase 0 暴露的动力学空白还在，Phase 2 才学它。
   另外注意：起始卦按定义是全场最共振的卦，所以"留在原地"永远是分数最高的选项；
   v1 要求至少走 1 步，否则答案永远是"不动"——这是一个人为的设定，不是发现。
3. **标签没审过。** 30 个提议演化是我一个人定的草稿。按 roadmap 第 6 节，
   需要 3 个人独立标注、不一致的丢掉或讨论——现在是 1 个人、0 轮讨论。
4. **接地文档很薄。** 每卦只有一句解读。共振的质量直接受限于这一句写得好不好；
   同一个情境换个说法，结果可能变。这是 v1 的已知弱点，不是 bug。
5. **LLM 基线没做（计划内的偏离）。** Roadmap 第 6 节要求盲测对比基线（直接问 LLM
   "这个情境接下来会怎样"），本阶段没做：它需要 API key 和盲评流程。
   报告格式已经预留了 `baseline` 字段（目前为 `null`），基线建好后填进去，不改 schema。
6. **没有古典卦辞。** 《易经》原文是三千年前的文本、属于公有领域，但所有能用的现代
   版本/翻译/注释都有版权，凭记忆抄写有抄到现代文本的风险。所以每卦的文档只有一句
   作者原创的现代解读；以后找到明确公有领域的古典来源并注明出处，再考虑加入。

## 怎么跑

```sh
# 编码器依赖（torch 较大，CPU 版即可；首次安装较慢）
pip install -e ".[dev]"

# 预建 embedding 缓存（首次运行自动建，也可手动）
python scripts/build_embeddings.py

# 对一个情境跑完整流程：匹配 + 推理 + 模板解释
python -m taiji_field.reasoning "两个部门为项目归属僵持了三周，谁也不让步"

# 跑整张卷子，写报告
python -m taiji_field.exam
# 只跑前 2 题：
python -m taiji_field.exam --limit 2

# 测试
pytest
```

## 自我 code review（标准 + 规格）

- **标准：** 模块按职责分开（grounding / reasoning / interpreter / exam），
  推理与解释分离；位约定沿用 Phase 0（阳=1、阴=0，L1..L6），没动 Phase 0 的代码；
  失败路径有回退（embedding 模型不可用时用字符 TF-IDF，并明说用的是回退）。
- **规格（对照 roadmap Phase 1）：** 情境→态编码器 v1 ✓；态→语言解释器 v1（模板）✓；
  意会推理 v1（共振 → 沿变爻边展开 1–3 步 → 路径 + 解释）✓；
  考试卷子 v1（30 题，人工标注合理演化——标注是草稿，待审）✓；
  盲测对比基线 ✗（未做，见第 5 条，已预留字段）。
  判据"可解释性明显更好，或准确率不输"目前无法判定：基线不存在，标签没审过。
  这是 Phase 1 结束时的真实状态，不是完成度 100%。
